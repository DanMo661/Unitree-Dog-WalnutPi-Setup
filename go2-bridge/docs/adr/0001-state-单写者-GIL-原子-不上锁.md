# ADR-0001: 共享 state 单写者 + GIL 原子赋值，不上锁

- 状态: 采纳
- 日期: 2026-10-31
- 关联: bridge.py（state 对象）、ARCHITECTURE.md 状态分布表

## 背景

bridge 的共享状态对象被四类线程同时读写：WebRTC 回调线程（遥测写入）、WS 会话线程（网页轴量）、
TRICK UDP 线程（收 go2-audio/pa_recv 进程请求）、主控制循环。曾讨论加锁保护。
（注意：pa_recv 是**独立进程**，只经 HTTP /state 只读快照，与桥不同进程，不在本 ADR 范围。）

## 决策

不上锁。每个字段有**唯一写者线程**；跨线程写只允许"单属性原子赋值"这一种形式；
读-改-写复合操作只允许发生在该字段的唯一写者线程内。读侧允许拿到毫秒~百毫秒级陈旧值。

## 理由

- CPython GIL 保证单属性赋值（一条 STORE）原子，读侧要么旧值要么新值，不会撕裂。
- 锁一旦扩散到 snapshot 拼装热路径，每帧多次加解锁，且回调线程持锁时容易重入死锁——
  狗控制链路的卡顿代价远大于偶尔显示陈旧值。
- 业务侧对陈旧读有兜底：显示层带 fresh/时间戳字段，安全层用独立的时间戳判活，不依赖"读到最新值"。

## 权衡

- **复合操作仍需小心**：`d.x += v` 这类读改写跨线程就是竞态，禁止。
- 多字段一致性更新（如统计环形桶重组）必须先在局部把新对象拼好，再一次整体赋值替换引用，
  不允许逐字段原地改让读者看到中间态。
- 这个决策在"引入真正的多进程"或"移除 GIL 的解释器"上失效，届时必须重开本 ADR。

## 后果

新增 state 字段时必须在 ARCHITECTURE.md 状态分布表登记唯一写者（该表现无"写者"列且行号已过期，
随轨道二拆分一并刷新——登记义务本身不变）；
code review 检查点：谁写、谁读、是否单属性赋值。
