# ADR-0002: 控制源切换后首帧只记电平，不合成边沿

- 状态: 采纳
- 日期: 2026-10-31
- 关联: netrc.py / pa_recv.py / bridge.py 两处主循环帧仲裁（旧 rc_loop 与 _rc_loop_active）+
  core/fsm.py frame() 播种（active 现役路径；bridge.py rc_loop 内播种块随旧路径退役）、
  test_netrc_sim.py、test_unlock_sim.py

## 背景

控制源有三种：SBUS 实体遥控器、App 网络遥控（15010）、网页遥控（WS）。
App 和实体遥控器可能**同时在线**。若把新源的首帧直接当电平边沿处理，
两个源各自的旧电平会拼出假边沿（解锁/上锁/模式切换互相触发），表现为双在线互踢振荡。

## 决策

控制源切换（含首次上线）后的**首帧只播种电平**：记录该源首帧的 A/C/B 通道电平作为基线
（prev_high/stand_prev/key_high），不产生任何边沿动作；每次换源用新源首帧重采基线；
边沿判定从该源第二帧起才参与。

## 理由

- 对方源的电平是"旧事实"，拿新源首帧和它拼边沿得到的是合成假边沿，不是任何一方的真实意图。
- 播种后新源拿到与自身一致的新基线，之后谁先动谁拿控制权，天然消振荡。

## 权衡

换源后第一条真实指令最多延迟一个帧周期（毫秒级），操作上无感，接受。

## 后果

改控制源仲裁逻辑时不得绕过播种步骤；
`test_netrc_sim.py` / `test_unlock_sim.py` 锁定"首帧不触发解锁"行为。
