# ADR-0008: 入口模块别名——`python bridge.py` 下惰性 `import bridge` 的双实例陷阱

- 状态: 采纳
- 日期: 2026-11-02
- 关联: bridge.py 入口守卫（sys.modules 别名行）、link.py:217 / webserver.py 三处惰性 import、
  test_entry_alias.py（源码形态守门）、2026-11-02 上板冒烟记录

## 背景

拆分后 link.py/webserver.py 用惰性 `import bridge`（在回调/请求路径里取 `_ACTIVE`、`dog`、
`_ctl_snapshot` 等全局）。本机与 webface 测试全绿；2026-11-02 首次真机 web 冒烟却发现：
web arm 的指令段生效（StandUp/BalanceStand 正常下发，狗确实站起来了），但 FSM 半段
`_f.web_cmd("arm")` 静默没跑——`web_armed` 在 250ms 内被主循环镜像刷回 False，
journal 无痕、无 err 回包。

## 决策

`python bridge.py` 作入口运行时，模块名是 `__main__` 而非 `bridge`；惰性 `import bridge`
会加载**第二份副本**（其 `_ACTIVE/dog` 全 None）。入口守卫必须在其任何线程启动前执行：

```python
if __name__ == "__main__":
    import sys as _sys
    _sys.modules["bridge"] = _sys.modules[__name__]   # 真身别名, 删=网页控制静默残废
    main()
```

使两处惰性 import 拿到的都是运行中的这一份。

## 理由

- 模块缓存按名字索引；`__main__` 与 `bridge` 是两个名字、两份命名空间。
- 一行别名是侵入性最小的修复；替代方案（把控制器显式传遍所有回调）是接口层重构，不划算。
- 为什么测试没拦住：webface 用例以**模块方式** `import bridge`（名字就是 bridge），
  天然单实例，复现不了；运行时等价审计（nitpick）核了"惰性 import 防循环"却默认了
  "同一对象"——该假设仅在以模块名启动时成立。

## 权衡

- `sys.modules` 别名是非主流手法，新人可能当 hack 删掉 → test_entry_alias.py 锁源码形态
  （删别名=红），并在入口处留了生命级注释。
- 别名后 `bridge` 模块的名字指向 `__main__` 实例；若有第三方代码 `import bridge` 拿到的是
  运行实例，正是我们想要的行为。

## 后果

- 新增守门测试 `test_entry_alias.py`；改 bridge.py 入口/link.py/webserver.py 的惰性 import
  前必跑。
- 教训进 nitpick 方法论：**入口是 `__main__` 时，模块自查出的"单例"结论不可信**，
  运行形态等价审计必须核对 `sys.modules` 视角。
- 真机回归清单新增场景候选：web arm 后 `web_armed` 持续为 true ≥5s（双实例探针）。
