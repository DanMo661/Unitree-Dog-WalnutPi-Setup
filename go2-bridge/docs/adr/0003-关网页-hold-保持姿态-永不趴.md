# ADR-0003: 关闭网页/网络会话 = hold 停走保持姿态，永不趴下

- 状态: 采纳
- 日期: 2026-10-31
- 关联: 91111d1（10-29 关页语义改 hold；该处改动仅落 bridge.py，同提交其余为鉴权等无关变更）、
  core/fsm.py `web_cmd("closed")`、FsmActive.hold()、
  test_fsm_table.py case 21/40、test_fsm_mode.py webface 契约

## 背景

10-29 起网页会话关闭从"趴下"改为"解除控制+停走保持姿态"（91111d1），但当时只改了 bridge.py 旧路径，
`core/fsm.py` 的 `web_cmd("closed")` 仍走 `set_mode(0)`（趴）。该漏网在 shadow 对拍中表现为
假 StandUp 分歧（10-31 归因修复）。行走中误关页面若触发趴下，高速下就是摔机。

## 决策

`closed` 语义统一为：解除 web 摇杆接管（清轴量、撤 web arm）+ 若狗**未被 RC 解锁**（armed=False）
且在链（link_up）则 `hold()`（速度清零、保持当前姿态）——RC 解锁期间关页不得抢着停走。
**趴下只认显式命令/档位**：三段开关拨到趴（C 下降沿）、A 键上锁（下降沿）、网页 disarm/damp
（test_fsm_table case 22：网页 damp → StandDown → M0）。会话关闭、断开、超时、失控保护、丢帧一概不趴。

## 理由

- 摔机是硬损伤，不可逆；趴下的收益（省电）远不抵风险。
- "停走保持姿态"与失控保护（0.25s/0.55s）用的是同一兜底动作，语义统一，没有第二套要理解的路径。
- 站立保持功耗用户可接受；用户随时可 A 键主动趴。

## 权衡

关页后狗保持站立姿态直到用户处理（或 30s 真失联上锁，同样是保持姿态）。接受。

## 后果

三处必须语义一致：`core/fsm.py web_cmd("closed")`、FsmActive.hold()、bridge.py WS 会话 finally 钩子。
test_fsm_table（case 21 关页保持 / case 40 在链关页 hold）与 test_fsm_mode webface 契约锁定；
改任何一处先跑这两套。
