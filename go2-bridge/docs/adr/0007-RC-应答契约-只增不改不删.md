# ADR-0007: 15001 行协议应答字段只增不改不删

- 状态: 采纳
- 日期: 2026-10-31
- 关联: pa_recv.py（RC 应答 v48）、android-app ManualCtrlActivity.java（parseSoc）、README.md 协议节

## 背景

v48 给 `RC` 应答追加了 soc（狗电量，未知=-1）与 fresh（离狗数据是否新鲜）两个字段。
v47 老客户端按空格 split 后忽略多余字段，不受影响——这次平滑升级验证了 append-only 的价值。

## 决策

`RC` 及所有 15001 行协议应答：**字段只增、不改、不删**。追加语义正确的字段天然向后兼容。
破坏性变更（改字段位置/语义/删除）必须：App 升版（APP_VERSION）+ `deploy_page.py` 上架同步，
且新版本铺开前板端保留旧字段不动。

## 理由

- App 与板固件版本长期错位（App 没有强制更新通道，用户可能几个月不更），
  append-only 是唯一不需要版本协商/握手就能演进的方式。
- 一次升级实测成本 ≈ 0（老客户端直接忽略），证明这条路的摩擦最小。

## 权衡

单条应答字段数有实际上限（RC 现 5 字段，继续膨胀会把"哪个位置是什么"变成猜谜）。
再要加信息时倾向开新命令（如 RC2）而不是无限追加。接受"偶尔开新命令"的代价，避免协议版本握手复杂化。

## 后果

改 15001 协议先对照本 ADR 判定是"追加"还是"破坏性"；
App 侧解析函数（split 后按下标取）一律按"多余字段忽略、缺字段按未知处理"书写。
