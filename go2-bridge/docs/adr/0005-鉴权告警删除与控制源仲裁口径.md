# ADR-0005: 鉴权告警删除 + 控制源仲裁的真实口径

- 状态: 采纳（2026-10-31 夜 nitpick-① 返修：原文"SBUS 恒最高优先级"与实现不符，按代码改写）
- 日期: 2026-10-31
- 关联: 1c030c7（删『未设鉴权』告警 + 修 _reject 炸接收线程）、languard.py、
  config.py NETRC_PORT 注释、bridge.py 两处主循环帧仲裁

## 背景

languard（护 web/netrc/pa 三入口的 NetGuard：token + IP 白名单，可选）未配置 token 时，
启动日志曾告警"未设鉴权"。用户定案：该告警删除（1c030c7）。本 ADR 记录依据，防止后续 agent
当漏配修回去；同时把控制源仲裁的代码真实口径写清——初版 ADR 写的"SBUS 恒最高优先级"
被审计证伪（config.NETRC_PORT 注释明写"新鲜时优先于 SBUS 线"）。

## 决策

1. languard 的 token + IP 白名单保持**可选**（未配置 = 放行，遗留行为兼容）；
   "未设鉴权"启动告警删除，`assert_configured` 退化为 no-op；门禁本体（配置了 token 就校验）不变。
2. **帧仲裁真实口径（以代码为准）**：主循环每拍 `f = sbus.read(); nf = netrc.get()`，
   **App 网络源帧新鲜（≈300ms 窗口内）时整体替代 SBUS 帧**（旧 rc_loop 与 _rc_loop_active 同款写法）；
   App 停发/过期后 SBUS 帧立即恢复生效。SBUS 的不可替代地位 = 物理兜底 + 越权门槛：
   网页指令越不过 RC 解锁态（core/fsm web_cmd 在 armed 时直接拒绝）。

## 理由

- 遥控器在用户手里就是授权的物理证明；鉴权防的是"家里别人误开页面"，不是攻击者。
- 常年响的告警只会训练所有人忽略警告，比没有告警更糟。
- 板子只在内网可达，无公网暴露面。

## 权衡

- **App 持续发包期间，SBUS 翻拨不生效**——夺回控制需先停 App 侧发送（关页面/停操控）。
  这是当前设计而非缺陷，但操作上必须知道；2026-11-01 真机回归顺带实测一次该窗口的行为。
- 局域网内任何设备都能开网页控制——接受，因为有 RC 解锁态门槛 + 无 SBUS 时失控保护仍兜底。

## 后果

若未来板子端口映射到公网 / 接入不可信网络，本 ADR 前提失效，必须重开（先加回门禁再谈别的）。
test_languard.py 锁定"配置了 token 必校验"的半边行为。
